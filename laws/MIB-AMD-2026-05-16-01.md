## Rationale

The 13-step fresh terminal sequence in §III Rule 3, as amended by MIB-AMD-2026-05-03-01, was authored before POSSESSIO's Chainlink Automation integration. Both `src/POSSESSIO_v2-4.sol` and `src/PossessioPayments_v2-2.sol` now import `AutomationCompatibleInterface` from `@chainlink/contracts/src/v0.8/automation/AutomationCompatible.sol`. The remapping points to `lib/chainlink-brownie-contracts/contracts/`, but the canonical sequence does not install this library — producing a "File not found" build error on first compile.

Discovered during the SCH ratification cycle (May 15–16, 2026 session): `compile__32_.txt` showed `ParserError: Source "lib/chainlink-brownie-contracts/contracts/src/v0.8/automation/AutomationCompatible.sol" not found` after the full canonical 13-step sequence. Adding `forge install smartcontractkit/chainlink-brownie-contracts` resolved the import resolution — verified by `compile__33_.txt`, which advances past the chainlink import error to surface a separate (unrelated, expected) test-file symbol error in `test/PossessioPayments.t.sol`.

This amendment updates the canonical sequence from 13 steps to 14 steps, inserting the chainlink-brownie-contracts install after the existing forge installs and before the hookmate install. The expanded sequence is verified at the import-resolution layer; full-green verification against the 585 test baseline pends the in-flight remediation of the obsolete `dispatchSweep` / `NotSelf` test references in `test/PossessioPayments.t.sol`, which is unrelated to this install step.

## Verification

The amended sequence is verified at the import-resolution layer for this amendment's specific scope:

- `compile__32_.txt`: Without the chainlink-brownie-contracts install, the build fails at the `AutomationCompatible.sol` import in both `POSSESSIO_v2-4.sol` (line 71) and `PossessioPayments_v2-2.sol` (line 74). `ParserError: Source "lib/chainlink-brownie-contracts/contracts/src/v0.8/automation/AutomationCompatible.sol" not found`.
- `compile__33_.txt`: After running `forge install smartcontractkit/chainlink-brownie-contracts` and re-running `forge build`, the compiler advances past the chainlink import. 125 files compile. The next surfaced error (`Member "NotSelf" not found ... in type(contract PossessioPayments)` at `test/PossessioPayments.t.sol:1608`) is an obsolete-test-symbol issue unrelated to the install step and is being remediated separately in the same session.

Full-green verification against the current 585 test baseline pends the orphan-symbol remediation. This amendment documents the install-step gap as it has been verified to exist and to resolve as specified; downstream verification follows the standard cycle once the remaining in-flight remediation lands.
