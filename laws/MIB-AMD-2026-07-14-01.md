## Background

Before this amendment, MIB assumed one execution substrate: the Architect's phone driving a GitHub Codespaces terminal, with AI seats operating as advisors who produce commands for the Architect to run. Every terminal rule in §III (one command per block, fresh-terminal sequence, stall list, tee+grep) is a discipline for *that* topology: intelligence upstream, hands downstream, both on the phone.

On July 14, 2026, a second topology operated for a full session arc: a **Claude Code session** — a Code Integrity seat with its own terminal, its own network access, and its own git identity, executing directly inside a cloud container holding a fresh clone of the repo. The seat ran the audit, the remediation, the test suites, the commits, the push, and the final production verification itself, returning to the Architect only at ratification boundaries.

The arc this amendment documents:

- Full-repo audit produced as a committed artifact (`AUDIT_20260714.md`), findings ranked and line-cited.
- Remediation of every code-fixable finding across four disjoint scopes, executed as seat-issued sub-work-orders running in parallel.
- Test baseline advanced 739 → **765 passed / 0 failed / 2 skipped** across 37 suites (arc across MIB history: 487 → 585 → 621 → 690 → 765).
- Seven commits pushed to a designated branch; PR #15 opened; **Architect ratified by merging** — from the phone.
- Production secret (`STATUS_KEY`) deployed via the Codespaces bridge; final verification executed by the Claude Code session directly when mobile paste truncation blocked the Architect's curl.

The topology is different enough that applying §III's rules to it verbatim is wrong in places (Rule 1's one-command-per-block exists because a *human on a phone* is the executor; a Claude Code seat batching its own commands loses nothing), and missing rules in others (nothing governed commit cadence, sub-work-order fan-out, or when the seat verifies production directly). Section X fills that gap.

Codebyte Law compliance note on provenance: this amendment is authored by the instance that performed the work, from its own session record, the same day. Every command shown was actually run; every failure mode shown was actually hit.

## §III Rule 3 — Alternate Sequence C (Claude Code environment)

The canonical Codespaces sequence (Rule 3, as amended through MIB-AMD-2026-05-16-01) remains canonical **for Codespaces**. A Claude Code session container differs in three load-bearing ways, verified this session:

1. **The repo arrives pre-cloned but submodules do not arrive initialized.**
2. **`foundryup` can fail with GitHub-API 403s** under the session's network proxy even when git cloning works. The official npm distribution of Foundry is the verified fallback.
3. **Dependencies are no longer `forge install`ed at setup** — as of the July 14, 2026 merge (PR #15), every dependency is a pinned submodule in `.gitmodules` + `foundry.lock` (openzeppelin, v4-core, v4-periphery, chainlink-brownie-contracts, base-std). The install chain in steps 4–8 of the Codespaces sequence is superseded by a single submodule init. (hookmate and its npm step were removed entirely in the same merge — nothing imports HookMiner since salt mining moved to CREATE3.)

**Sequence C — fresh Claude Code session:**

**1.**
```
git submodule update --init --recursive
```

**2.**
```
curl -L https://foundry.paradigm.xyz | bash && foundryup
```

**3.** *(only if step 2 fails with 403 / "failed to fetch release tags")*
```
npm install -g @foundry-rs/forge
```

**4.**
```
forge --version
```

**5.**
```
forge build 2>&1 | tee compile.txt
```

**6.**
```
forge test -vv | tee report.txt
```

Rule 6 (tee+grep surgical query, MIB-AMD-2026-05-20-01) applies unchanged and is *more* load-bearing here, since the seat reads its own reports: summary lines are verified against `grep -c "\[PASS\]"` substrate counts, never trusted alone. Fork suites self-gate: without `BASE_RPC_URL` they skip (this session repaired the one suite that hard-failed instead of skipping — the skip-gate is now uniform across all four fork suites).

**Note for Codespaces (Rule 3 body):** steps 4–10 of the 14-step sequence (the five `forge install`s, the hookmate cd/npm) are superseded by the same submodule reality. A future amendment should collapse the Codespaces sequence to match; this amendment only marks it, because this session did not re-verify the collapsed sequence *in Codespaces* and Codebyte Law bounds claims to what was verified.

## Section X. Claude Code Session Operation

### X.1 What a Claude Code session is, in council terms

A Claude Code session is a **Code Integrity seat with hands**. It holds the same seat scope (verification, implementation, test integrity, honest findings) but executes terminal work itself instead of producing commands for the Architect. The Architect's role is unchanged in kind — ratify direction, review at boundaries, decide what only the Architect can decide — but the review boundary moves from *per-command* to *per-artifact*: the commit, the pushed branch, the PR, the report.

The trust-level ladder (§II) applies. This session operated at Level 3 (autonomous leaf-turning) under the Architect's standing direction ("double check the entire repo," then "let's get these findings fixed"), returning at ratification points. **The PR is the ratification instrument:** the seat never merges; the Architect merges from the phone. A merged PR is Architect ratification in the exact §IV sense.

### X.2 Command discipline differences from §III

- **Rule 1 (one command per block) does not bind the seat's own execution.** It exists to protect a human copying commands on a phone. The seat batches, pipes, and background-runs freely — but any command it hands *back to the Architect* to run reverts to Rule 1 form: one per block, numbered, short lines (see X.5).
- **Rule 4 (explicit push + verify) binds harder.** Push is always explicit to the designated branch (`git push -u origin <branch>`), and landing is verified from output, never assumed.
- **Rule 5 (stall list) is largely moot** in the session terminal but still governs anything issued to the Architect's Codespace.
- **Leaf-turning maps to commits.** One scope of work = one commit with a message that states findings fixed and evidence (test tallies). The between-leaf Pause maps to pushing the commit before starting the next scope — the remote branch is the locked artifact. Seven leaves were turned this way in the July 14 arc.

### X.3 Seat-issued sub-work-orders (parallel fan-out)

For work spanning disjoint scopes, the seat may issue **sub-work-orders to subordinate instances running in parallel**, in Section VIII form: deliverable, required reading, scope-in, scope-out (explicit file-path ownership), Codebyte constraints, success criteria, report-back.

The July 14 remediation ran four in parallel: contracts (`src/ test/ script/`), radar (`radar/` + one CI step), workers/MCP (`mcp/ mailer/ worker/ public/`), docs (root `*.md`, `LICENSE`, `.gitignore`). Two rules proved load-bearing:

1. **Path ownership is the state-race guard.** §II's leaf-turning prevents races in time; disjoint file ownership prevents them in space. Every sub-order names what it must NOT touch. No two orders share a file.
2. **The seat verifies the merged whole itself before committing.** Sub-order self-reports are substrate, not proof. After all four returned, the seat re-ran the full build, the full forge suite, and every node test suite, and spot-read the highest-risk diffs (the C-1 harvest math) before any commit. "Trust, then verify anyway" — a sub-instance's green claim is subject to the same substrate check as a summary line in report.txt.

Constraint carried in every sub-order, verbatim from this session: **"never fake a test green."** A pinned-hash or gas test that fails from a legitimate change gets its pin updated with a comment; it does not get deleted or loosened silently.

### X.4 Findings discipline

Unchanged from §IV/§V but with a sharper artifact rule: findings are committed to the repo as a ranked, line-cited document (`AUDIT_20260714.md` pattern — severity, `file:line`, one-sentence defect, concrete failure scenario) **before** remediation begins, and the remediation is recorded against it (which commits fixed which findings, what remains open and why). Items that require Architect authority (this arc: the calibration-privacy posture D-2, the RULEBOOK amendment D-3, the Farcaster signature W-3) are explicitly marked open and routed to TODO — the seat does not decide them, per §I: guessing Architect intent is a Codebyte Law violation.

### X.5 Mobile secret-deployment discipline (the bridge under stress)

Some operations cannot leave the Architect's hands — anything requiring the Architect's personal Cloudflare/GitHub authority (tokens, `wrangler secret put`, dashboard actions). These run in Codespaces on the phone, and the July 14 `STATUS_KEY` deployment surfaced four failure modes and their canonical answers:

**Failure 1 — browser OAuth cannot complete in Codespaces.** `wrangler login`'s localhost callback is unreachable. Canonical answer: never use browser login; create a scoped API token in the dashboard ("Edit Cloudflare Workers" template) and hand it to the terminal:

**1.**
```
export CLOUDFLARE_API_TOKEN=<token>
```

**2.**
```
npx wrangler whoami
```

`whoami` is the checkpoint; do not proceed past an auth error.

**Failure 2 — mobile paste truncates long lines,** silently, repeatedly, at roughly the same length (~54 chars observed, twice, same position). A 64-char key spliced into a one-line curl loses its tail and its closing quote. Canonical answer: **short lines and shell variables, with a length check as substrate:**

**1.**
```
KEY=<the 64-char value>
```

**2.**
```
echo ${#KEY}
```

Must print the expected length (64). If it does not, the paste truncated — re-paste until it does. Only then:

**3.**
```
curl -i -H "Authorization: Bearer $KEY" "$URL/status"
```

**Failure 3 — a `>` continuation prompt reads as a frozen terminal on mobile.** It is bash waiting for a closing quote from a mangled paste. Canonical unstick, in order: `Ctrl+C` from the keyboard toolbar; if no Ctrl is available, type a single `"` and press Enter — the broken command fails harmlessly and the prompt returns.

**Failure 4 — interactive prompts are hostile to mobile paste.** Pipe instead of pasting at prompts:

```
echo "<value>" | npx wrangler secret put STATUS_KEY
```

**The handoff rule (load-bearing):** when the mobile bridge fails the same operation twice, and the remaining step requires no Architect-personal authority — an HTTP check, a git operation, a test run — **hand it to the Claude Code session and stop fighting the phone.** The July 14 final verification (`404` without key, `200` with key) was executed by the session in one tool call after the phone had blocked the Architect for the better part of an hour. Fail-closed semantics were confirmed: locked `/status` returns a bare 404, indistinguishable from a missing route.

**Exposure rule:** a secret that transits chat or a screenshot is burned-but-serviceable — deploy it to unblock, log a rotation obligation, rotate from a clean channel later. `openssl rand -hex 32 | npx wrangler secret put STATUS_KEY` re-keys in one line with no redeploy. A *root* credential (the Cloudflare account token) must never transit chat or screenshots at all; there is no "rotate later" posture for the key to the whole account.

### X.6 Division of labor doctrine

Ratified in practice July 14, 2026, stated plainly: **the session is the computer.** Terminal-heavy work — builds, test suites, audits, refactors, commits, pushes, HTTP verification — routes to Claude Code sessions by default. Codespaces on the phone is reserved for operations that constitutionally require the Architect's own credentials, executed under X.5 discipline with the seat pre-filling every command literal. The Architect's attention (§VI: finite) is spent where only the Architect has authority: ratification, merges, tokens, and the decisions no seat may make.
