## What got fixed

### N-1 (was HIGH) — council ledger POST unauthenticated + replayable → **FIXED (core threat closed)**
The two root causes are both eliminated:
- **Replay killed at the DB.** Migration `0025_council_ledger_nonce_unique.sql` adds
  `UNIQUE INDEX (seat, nonce)`; `worker/index.ts:286-295` wraps the INSERT and maps the
  constraint violation to a clean **409 `NONCE_ALREADY_USED`** (not a 500). Re-posting a
  harvested `(seat, body, nonce, signature)` now dies at the index.
- **Nonce canonicalization closes a hex/dec bypass** (a bug that could have defeated the
  above): `:285` stores `BigInt(nonce).toString()`, so `"42"` and `"0x2a"` — which recover
  the same signer — collide in the index instead of slipping through as distinct strings.
  Correctly pre-empted.
- **Auth now fail-closed.** `wrangler.jsonc:25` sets `COUNCIL_SEATS` to the four SAV seats;
  `worker/index.ts:271-274` returns **503 `ALLOWLIST_UNCONFIGURED`** on an empty allowlist
  (previously the check was *skipped* when empty — the "any signer can post" gap) and **403
  `NOT_A_SEAT`** otherwise. An anonymous party can no longer write at all.
- GET still returns `signature`+`nonce`, now safe by design (replay is blocked at the index,
  not by hiding the material — the intended independently-verifiable ledger).

**Residual — NOW CLOSED (2026-07-24, same branch):** `kind`/`ref` were uncapped (only `body`
was bounded) and the POST had no rate limit, leaving a compromised seat key able to grow the
shared radar D1 unbounded — the same DB whose size ceiling halted every radar write on
2026-07-16. Both closed in `worker/index.ts`: `kind` ≤ 32 chars / `ref` ≤ 256 chars
(`KIND_TOO_LONG` / `REF_TOO_LONG`, 400), and a per-seat rate limit of 20 posts / 60s
(`RATE_LIMITED`, 429) enforced **after** the signature + allowlist gates — so an
unauthenticated caller can never consume a real seat's budget, and the extra D1 read only
runs for a proven seat. The ledger is its own rate-limit state (no new binding; the counter
cannot drift from what was actually written). N-1 is now closed end to end.

New code that shipped alongside was reviewed clean: the `feed_status` write path (migration
0026 + `radar/index.ts:44-69`, parameterized, hardcoded scan keys), the `discoveryScan`
FK-crash fix (`radar/watcher.ts:165-182`), and the whole new desk surface (pump.fun images,
dev address/name, Sell button, autofit) — every attacker-controlled field routes through
`esc()` before `innerHTML`, so it is XSS-clean.

`radar/watcher.ts:72-79`. The >4KB slimmed subset still omits `associated_bonding_curve`,
which `radar/screen.ts:494` reads to exclude the bonding curve from the float. With it null,
the curve (largest pre-graduation account) is scored as the top holder → `gate_rug = 0`
(false rug fail) → `strat_take` suppressed. **Every birth payload over 4KB (a long creator
description is enough) is still silently mislabeled a rug fail in the calibrated ledger.**
The fix's own comment at `radar/watcher.ts:186` says the rug gate pulls that field — yet the
slimming omits it. One-field fix. *This is the highest-value open item: it silently corrupts
the exact ledger the calibration exists to keep honest.*
